02 环境部署篇 · 第 8 章：报错急救手册：环境变量 / 端口占用 / 权限问题

← 上一章 ｜ 返回目录

这章解决什么问题

环境部署的疑难杂症合集。装任何软件卡住了，先来这里对号入座——新手卡住的报错大多就是这十来种，同一个病根换了个说法。

一、环境变量类："不是内部或外部命令"

症状：

'python' 不是内部或外部命令，也不是可运行的程序或批处理文件。

node、git、javac、mysql 同理。

病根：系统在 PATH 列出的目录里找不到这个程序。

急救顺序：

  1. 先重开终端——改完环境变量旧窗口不生效，这是最高频的坑。
  2. 确认软件真的装了：去安装目录里亲眼看 xxx.exe 在不在。
  3. 补 PATH：Win 搜"编辑系统环境变量" → 环境变量 → Path → 新建一行 → 填软件的 bin 目录（如 C:\Program Files\MySQL\MySQL Server 8.0\bin）。⚠️ 改之前先把当前 Path 的值整段复制到记事本存一份，改坏了能原样贴回去。
  4. 再重开终端验证。

排查命令：

where.exe python      # 系统找的是哪个 python，路径对不对
echo $env:Path        # 看现在的 PATH 里有没有你的目录

⚠️ 两个经典变种：

  • 输 python 弹出微软商店 → 设置 → 应用 → 高级应用设置 → 应用执行别名，关掉 python 相关开关。
  • where python 找到了但版本不对 → PATH 里有两个同名程序，排在前面（上边）的优先，把对的挪上去。

二、端口占用类："Address already in use"

症状：port 3306 is already allocated / Port 8080 was already in use / 程序启动报 bind:10048。

病根：另一个程序占了这个端口（可能就是你上次没关的服务）。

急救三连：

# 1. 查谁占了端口（以 3306 为例）
netstat -ano | findstr :3306
# 输出最后一列是 PID（进程号）

# 2. 看这个 PID 是什么程序
tasklist | findstr 12345     # 把 12345 换成你的 PID

# 3. 是垃圾就杀，是自己要用的服务就 stop 服务
taskkill /PID 12345 /F

常见占用惯犯：3306（旧 MySQL）、8080（Tomcat/其他后端）、7897（你的代理客户端本身，别杀）、80（IIS/Skype 老版本）。

💡 不确定能不能杀？taskkill 之前先 tasklist 确认，杀错系统进程会蓝屏级别难受。

三、权限类："拒绝访问 / Access denied"

症状解法
nvm use 无反应/报错nvm 需要管理员 PowerShell（Win+X → 终端(管理员)）
往 C:\Program Files 写文件失败该目录受保护：右键"以管理员身份运行"，或干脆把工作目录放到 C:\code\ 这种非系统区
Set-ExecutionPolicy 报错同样需要管理员窗口
Git push 报 403仓库没权限：检查远程地址用户名、token 权限是否含 repo
删文件说被占用开资源监视器（Win 键搜 resmon）→ CPU 标签 → 在"关联的句柄"搜索框输入文件名，就能揪出是哪个程序占着它

## 四、网络类："下载慢 / 超时 / 证书错误"

症状解法
pip / npm / git 下载龟速换国内源：本篇第 2、3 章都有现成命令
GitHub clone 超时第 1 章的 Git 代理三行命令
docker pull 超时第 6 章镜像加速
报 SSL certificate problem先确认系统时间对不对（错一年必然证书错）；w32tm /resync
装一半断网失败重跑安装器前先删半成品目录，避免残留冲突

## 五、玄学类："之前好好的，突然就不行了"

按命中率排序：

  1. 重开终端（改了配置没生效）
  2. 重启软件
  3. 重启电脑（Docker/WSL 类问题的特效药）
  4. 想想刚才装了/卸了什么 → 回滚那个操作
  5. 还不行 → 把完整报错原文复制下来，去本仓库提 Issue

## 六、防患于未然：四条军规

  1. 安装路径永远全英文，别带空格和中文（C:\code\ 而不是 C:\新建文件夹\我的 程序\）。
  2. 一个软件只装一份，装新版本先卸旧版本（Node/Java 重灾区）。
  3. 改环境变量后必重开终端。
  4. 报错先看第一行，把原文复制下来搜索/提问，别截图抠字。

## ✅ 验证：你有急救能力了

不看上文回答：

  • node 不是内部命令，急救第一步是什么？（重开终端）
  • 8080 被占，三连命令是什么？（netstat -ano | findstr :8080 → tasklist | findstr PID → taskkill /PID x /F）
