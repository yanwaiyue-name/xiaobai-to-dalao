02 环境部署篇 · 第 3 章：Node.js 环境部署（nvm 管理）

← 上一章 ｜ 返回目录 ｜ 第 4 章：Java 环境部署 →

这章解决什么问题

  • 用 nvm 装 Node.js：以后新版本随便升、旧项目随时切，不用卸了装装了卸
  • npm 换国内源，装依赖不再龟速

为什么用 nvm 而不是官网安装包

Node.js 的版本特别多：新项目要 20.x，老项目只跑得动 16.x。官网安装包一次只能装一个版本，换版本就得卸了装、装了卸。nvm（Node Version Manager，版本管理器）让你多个版本共存、一条命令随时切换。

第 1 步：卸载已有的 Node（如果装过）

控制面板 → 卸载 Node.js。⚠️ nvm 的工作方式是"包办"你电脑上所有的 Node，如果还残留着一个官网装的 Node，两套会打架导致切换失效，所以必须先卸干净。

第 2 步：安装 nvm-windows

  1. 下载：https://github.com/coreybutler/nvm-windows/releases → nvm-setup.exe。
  2. 双击安装，路径保持默认（或全英文路径），完成。

✅ 验证

以管理员身份打开 PowerShell：

nvm version

输出版本号即成功。

⚠️ nvm-windows 的很多操作需要管理员权限，以后凡是用 nvm，都用管理员 PowerShell。

第 3 步：先给 nvm 换国内源（重要）

nvm node_mirror https://npmmirror.com/mirrors/node/
nvm npm_mirror https://npmmirror.com/mirrors/npm/

不换的话，下一步下载 Node 大概率龟速或失败。

第 4 步：安装 Node.js LTS 版本

nvm list available        # 看看有哪些版本（找 LTS 标记的）
nvm install lts           # 直接装当前最新 LTS，不用背版本号
nvm list                  # 看刚装好的具体版本号
nvm use 22.14.0           # 启用它：把 22.14.0 换成你 nvm list 里实际的版本号

✅ 验证

node --version    # 显示 v22.x / v24.x 等 LTS 版本号即可
npm --version     # 有版本号即可，不必和教程一致

⚠️ 别照抄老教程装 Node 20：它已在 2026 年 4 月停止维护。新装就用上面的 nvm install lts。

💡 以后想升级：再跑一次 nvm install lts，然后 nvm use 新版本号，旧版本还在，随时切回。

第 5 步：npm 换国内源

npm config set registry https://registry.npmmirror.com

验证：

npm config get registry    # 应输出 npmmirror 地址

第 6 步：跑第一个程序

mkdir C:\code\node-demo
cd C:\code\node-demo
npm init -y                # 生成 package.json
npm install axios          # 装第一个依赖
node -e "console.log('Node 跑起来了')"

常见坑

现象解法
nvm use 后 node 仍不是内部命令没用管理员权限，或第一步的旧 Node 没卸干净
nvm install 下载失败/超时第 3 步的镜像没配，回去配置
npm install 卡住换源（第 5 步）；还不行删掉项目里的 node_modules 和 package-lock.json 重装
项目报 node-sass 安装失败老项目依赖，npm config set sass_binary_site https://npmmirror.com/mirrors/node-sass/ 再装
全局装的包找不到npm config get prefix 看路径，确认该路径在 PATH 里（nvm 路径会自动接管）

## ✅ 验证全部完成

nvm list          # 能看到你装的版本且带 * 号（当前使用）
node --version    # 有版本号
npm --version     # 有版本号
npm config get registry   # npmmirror 地址
